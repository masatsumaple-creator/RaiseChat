| 項目 | 内容 |

| 作成日 | 2026-11-23 |

## 1. 概要・目的・スコープ

### 1.1 目的
Slack 風のワークスペース型チャットアプリ「RaiseChat」を開発する。個人開発・小規模チーム(同時接続数十人程度)での利用を想定する。

### 1.2 スコープ
- 対象: Web ブラウザ(PC 中心)で動作するチャットアプリ
- 対象外:
  - ボイスチャンネル
  - メール認証、パスワードリセットメール
  - ネイティブ/モバイルアプリ
  - ブラウザ外の通知(メール通知、モバイルプッシュ)

## 2. 用語定義

| 用語 | 意味 |
|---|---|
| ワークスペース | チャンネル・メンバーを束ねる最上位の単位 |
| チャンネル | ワークスペース内の会話の場。パブリック(誰でも参加可)/プライベート(招待制) |
| DM | ワークスペース内のユーザー間の1対1の会話 |
| スレッド | 特定メッセージへの返信の連なり |
| オーナー | ワークスペースの作成者。管理者権限を持つ |
| メンバー | ワークスペースに参加している一般ユーザー |

## 3. ロールと権限

| 操作 | オーナー | メンバー | 非メンバー |
|---|:-:|:-:|:-:|
| ワークスペース作成 | ○(誰でも作成可、作成者がオーナー) | - | - |
| メンバーの招待 | ○ | ○(※1) | × |
| メンバーのキック | ○ | × | × |
| チャンネル作成 | ○ | ○ | × |
| チャンネル削除 | ○ | ×(※2) | × |
| パブリックチャンネルの閲覧・投稿 | ○ | ○(参加後) | × |
| プライベートチャンネルの閲覧・投稿 | ○(参加者のみ) | ○(参加者のみ) | × |
| 自分のメッセージの編集・削除 | ○ | ○ | × |
| 他人のメッセージの削除 | 未決(§9) | × | × |

※1 要件では「オーナーの操作」として定義されているため、メンバーの招待可否は未決(§9)。暫定はオーナーのみ。
※2 要件上、チャンネル削除はオーナーのみ。

## 4. 機能要件

優先度: **M**=MVP 必須 / **S**=MVP 後に対応

### 4.1 認証・ユーザー管理

| ID | 要件 | 受入基準 | 優先度 |
|---|---|---|---|
| FR-001 | 新規登録 | ユーザー名+パスワードで登録できる。ユーザー名は一意。メール認証は行わない | M |
| FR-002 | ログイン | 登録済みのユーザー名+パスワードでログインできる。誤りは理由を特定しない文言でエラー表示 | M |
| FR-003 | ログアウト | ログアウト後、認証必須ページにアクセスできない | M |
| FR-004 | プロフィール設定 | アバター画像・表示名・ステータス(テキスト)を変更できる。変更は他ユーザーの画面に反映される | M |

### 4.2 メッセージング

| ID | 要件 | 受入基準 | 優先度 |
|---|---|---|---|
| FR-101 | チャンネル内テキストチャット | 参加チャンネルに投稿でき、他の参加者に即時(数秒以内)表示される | M |
| FR-102 | ダイレクトメッセージ | 同一ワークスペースのユーザーと1対1で会話できる | M |
| FR-103 | メッセージ編集 | 自分のメッセージを編集でき、「編集済み」と表示される | M |
| FR-104 | メッセージ削除 | 自分のメッセージを削除でき、他ユーザーの画面からも消える(方式は§9) | M |
| FR-105 | スレッド返信 | メッセージに対しスレッドで返信できる。親メッセージに返信数が表示される | M |
| FR-106 | マークダウン記法 | 太字・斜体・取り消し線・コード(インライン/ブロック)・リスト・引用・リンクを表示できる。HTML は無害化する | M |
| FR-107 | ファイル添付(画像・動画) | 画像・動画を添付でき、メッセージ内でプレビュー/再生できる。サイズ・形式の制限は§9 | M |
| FR-108 | 絵文字リアクション | メッセージに絵文字を付与/解除できる。付与者と件数が表示される | M |
| FR-109 | メンション | `@ユーザー名` で同一チャンネル/ワークスペースのユーザーを指定でき、入力中に候補が補完される。表示は強調される | M |
| FR-110 | メッセージ検索 | 本文のキーワード検索ができる。結果は自分が閲覧権限を持つチャンネル/DM のメッセージに限る | M |

### 4.3 ワークスペース・チャンネル管理

| ID | 要件 | 受入基準 | 優先度 |
|---|---|---|---|
| FR-201 | ワークスペース作成 | 名前を指定して作成でき、作成者はオーナーになる。初期チャンネル(例: general)が作られる | M |
| FR-202 | チャンネル作成 | 名前と種別(パブリック/プライベート)を指定して作成できる。同一ワークスペース内で名前は一意 | M |
| FR-203 | パブリックチャンネル参加 | メンバーはパブリックチャンネル一覧から自由に参加/退出できる | M |
| FR-204 | プライベートチャンネル招待 | 招待された人のみ参加でき、非参加者には一覧・検索・メンションの候補に現れない | M |
| FR-205 | 友人の招待 | ワークスペースに友人を招待できる(方式は§9、暫定は招待リンク) | M |

### 4.4 管理者権限(オーナー)

| ID | 要件 | 受入基準 | 優先度 |
|---|---|---|---|
| FR-301 | ユーザーの招待 | オーナーがワークスペースへユーザーを招待できる | M |
| FR-302 | ユーザーのキック | オーナーがメンバーを強制退出させられる。キックされたユーザーは直ちにアクセス不可になる。オーナー自身はキック不可 | M |
| FR-303 | チャンネルの追加・削除 | オーナーがチャンネルを追加・削除できる。削除時は確認ダイアログを表示する | M |

### 4.5 通知(ブラウザ上のみ)

| ID | 要件 | 受入基準 | 優先度 |
|---|---|---|---|
| FR-401 | 未読通知 | 未読メッセージがあるチャンネル/DM にバッジ(未読数)を表示する。既読位置はチャンネル単位で保存し、別端末でも共有される | M |
| FR-402 | メンション通知 | 自分宛メンションを強調バッジで表示する。ブラウザの Notification API による通知(ユーザー許可制)を行う | M |
| FR-403 | 通知設定 | チャンネル単位のミュート | S |

## 5. 非機能要件

前提: 個人開発・小規模(同時接続数十人、ワークスペース数個〜十数個)。

| 区分 | 要件 |
|---|---|
| 性能 | 投稿から他クライアント表示まで通常 1 秒以内(目標)。履歴はページング(例: 50件/回)で取得 |
| セキュリティ | パスワードは bcrypt/argon2 でハッシュ化。HTTPS 前提。XSS(マークダウンの無害化)・CSRF・SQL インジェクション対策。全 API で「ワークスペース/チャンネル所属」の認可チェックを行う(IDOR 対策)。ログイン試行のレート制限 |
| ファイル | 拡張子だけでなく MIME/マジックナンバーも検証。サイズ上限を設ける。アクセスは認可付き URL |
| 可用性 | 個人開発のため高可用性は求めない。DB の定期バックアップを行う |
| 互換性 | 最新の Chrome / Edge / Firefox / Safari のデスクトップ版。モバイルは閲覧できる程度のレスポンシブ(S) |
| 保守性 | 認可・マークダウン変換など重要ロジックに自動テストを書く。CI で lint とテストを実行 |
| プライバシー | パスワード・トークンをログに出力しない |

## 6. データモデル概要

```
User ─< Membership >─ Workspace
Workspace ─< Channel ─< ChannelMember >─ User
Channel(DM 含む。種別: public / private / dm)
Channel ─< Message ─< Attachment
Message ─< Reaction (user, emoji)
Message ─< Mention (user)
Message(parent_id) ─ スレッド返信は親メッセージを参照
ChannelMember.last_read_message_id ─ 未読管理
Workspace ─< Invitation (token, expires_at)
```

| エンティティ | 主な属性 |
|---|---|
| User | id, username(unique), password_hash, display_name, avatar_url, status_text |
| Workspace | id, name, owner_id |
| Membership | workspace_id, user_id, role(owner/member) |
| Channel | id, workspace_id, name, type(public/private/dm) |
| ChannelMember | channel_id, user_id, last_read_message_id, muted |
| Message | id, channel_id, user_id, parent_id(nullable), body, created_at, edited_at, deleted_at |
| Attachment | id, message_id, kind(image/video), storage_key, mime, size |
| Reaction | message_id, user_id, emoji(複合ユニーク) |
| Mention | message_id, user_id |
| Invitation | id, workspace_id, token, created_by, expires_at, max_uses |

DM は「2人だけの type=dm の Channel」として扱い、メッセージ関連の機能(スレッド・リアクション・検索・未読)を共通化する。

## 8. 技術選定案

小規模・個人開発で、リアルタイム性と実装の単純さを重視した 1 案。

| 領域 | 採用案 | 理由 |
|---|---|---|
| 言語 | TypeScript(フロント・バック共通) | 型を共有でき、個人開発で学習コストが低い |
| フロント | React + Vite | エコシステムが豊富 |
| バックエンド | Node.js + Fastify(または Express) + WebSocket(Socket.IO など) | リアルタイム配信を同一プロセスで扱える |
| DB | PostgreSQL | リレーショナルなデータに適し、全文検索機能(日本語は pg_bigm / pg_trgm で対応)も使える |
| ORM | Prisma または Drizzle | 型安全、マイグレーション管理 |
| 認証 | セッション Cookie(HttpOnly, SameSite) + argon2 | メール認証不要の構成で単純かつ安全 |
| ファイル保存 | 開発: ローカルディスク / 本番: S3 互換ストレージ | 抽象化して差し替え可能にする |
| 通知 | WebSocket + Notification API | ブラウザ内通知の要件に合致 |
| 検索 | 初期は PostgreSQL の部分一致/trigram | 小規模では外部検索基盤は不要 |
| テスト/CI | Vitest + Playwright(主要フロー)、GitHub Actions | 既存の CI 構成を活用 |

※ 技術スタックは提案であり、ユーザーの得意分野に応じて変更可能。

## 9. 未決事項・前提(暫定案つき)

| # | 論点 | 暫定案 |
|---|---|---|
| 1 | 招待方式 | 期限付き招待リンク(ユーザー名指定の招待は後回し) |
| 2 | メンバーも招待できるか | オーナーのみ(要件どおり) |
| 3 | 1ユーザーの複数ワークスペース所属 | 可。ユーザーアカウントはグローバル |
| 4 | オーナー譲渡・ワークスペース削除 | MVP 対象外 |
| 5 | プライベートチャンネルへの招待権限 | チャンネル参加者なら誰でも可 |
| 6 | 添付ファイル制限 | 画像 10MB / 動画 100MB、形式は jpg/png/gif/webp、mp4/webm |
| 7 | 検索範囲 | 自分が参加しているチャンネル+DM。パブリック未参加分は対象外 |
| 8 | 削除方式 | 論理削除。スレッド付き親は「削除されました」と表示して返信を残す |
| 9 | オーナーによる他人メッセージ削除 | MVP 対象外 |
| 10 | パスワード忘れ | リセット手段なし(メール認証なしのため)。MVP は割り切り、将来はオーナーによる再設定など検討 |
| 11 | キックされたユーザーの過去メッセージ | 残す(表示名はそのまま) |
| 12 | DM のグループ化(3人以上) | 対象外(1対1のみ) |

## 10. 開発フェーズ案

1. **基盤**: プロジェクト雛形、DB、認証(FR-001〜003)、CI
2. **コア**: ワークスペース/チャンネル、チャンネルチャット、リアルタイム配信(FR-101, 201〜204)
3. **メッセージ機能**: 編集/削除、スレッド、マークダウン、リアクション、メンション、DM(FR-102〜106, 108, 109)
4. **ファイル・検索**: 添付、検索(FR-107, 110)、プロフィール(FR-004)
5. **管理・通知**: 招待、キック、チャンネル削除、未読・メンション通知(FR-205, 301〜303, 401, 402)
6. **仕上げ**: セキュリティ確認、テスト整備、ミュート等の S 項目
