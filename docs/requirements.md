## 1. 概要・目的・スコープ

### 1.1 目的
Slack 風のワークスペース型チャットアプリ「RaiseChat」を開発する。$\color{red}{\text{個人開発・小規模チーム(同時接続数十人程度)での利用を想定する。}}$

### 1.2 スコープ
- 対象: Web ブラウザで動作するチャットアプリ
- 対象外:
  - ボイスチャンネル
  - メール認証
  - $\color{red}{\text{ネイティブ/モバイルアプリ、ブラウザ外の通知(メール・モバイルプッシュ)}}$

## 2. 用語定義

| 用語 | 意味 |
|---|---|
| ワークスペース | チャンネル・メンバーを束ねる最上位の単位 |
| チャンネル | ワークスペース内の会話の場。パブリック(誰でも参加可)/プライベート(招待制) |
| DM | ワークスペース内のユーザー間の会話 |
| スレッド | 特定メッセージへの返信の連なり |
| オーナー | ワークスペースの作成者。管理者権限を持つ |
| メンバー | ワークスペースに参加している一般ユーザー |

## 3. ロールと権限

| 操作 | オーナー | メンバー | 非メンバー |
|---|:-:|:-:|:-:|
| ワークスペース作成 | ○(作成者がオーナー) | - | - |
| ワークスペースへの招待 | ○ | $\color{red}{\text{×}}$ | × |
| メンバーのキック | ○ | × | × |
| キックの解除 | $\color{red}{\text{○}}$ | $\color{red}{\text{×}}$ | $\color{red}{\text{×}}$ |
| チャンネル作成 | ○ | $\color{red}{\text{○}}$ | × |
| チャンネル削除 | ○ | × | × |
| パブリックチャンネルの閲覧・投稿 | ○ | ○(参加後) | × |
| プライベートチャンネルの閲覧・投稿 | ○(参加者のみ) | ○(参加者のみ) | × |
| プライベートチャンネルへの招待 | $\color{red}{\text{○}}$ | $\color{red}{\text{作成者のみ ○}}$ | $\color{red}{\text{×}}$ |
| 自分のメッセージの編集・削除 | ○ | ○ | × |
| 他人のメッセージの削除 | $\color{red}{\text{×(MVP では不可。§9 #9)}}$ | × | × |

注: $\color{red}{\text{メンバーの招待権限は、要件が「オーナーの操作」と定めているためオーナーのみとした。メンバーへの開放は将来の検討事項。}}$

## 4. 機能要件

優先度: $\color{red}{\text{M=MVP 必須 / S=MVP 後に対応}}$

### 4.1 認証・ユーザー管理

| ID | 要件 | 受入基準 | 優先度 |
|---|---|---|---|
| FR-001 | 新規登録 | ユーザー名+パスワードで登録できる。メール認証は行わない。$\color{red}{\text{ユーザー名はサービス全体で一意。登録直後にリカバリーコードを一度だけ表示し、ハッシュで保存する(§9 #10)。}}$ | M |
| FR-005 | $\color{red}{\text{パスワードの再設定}}$ | $\color{red}{\text{リカバリーコードを入力して、ユーザー自身がパスワードを再設定できる。再設定すると、全セッションを失効させ、新しいリカバリーコードを一度だけ表示する。誤ったコードは理由を特定しない文言で拒否し、試行はレート制限する。}}$ | S |
| FR-002 | ログイン | 登録済みのユーザー名+パスワードでログインできる。$\color{red}{\text{誤りは理由を特定しない文言でエラー表示する。}}$ | M |
| FR-003 | ログアウト | ログアウト後、$\color{red}{\text{認証必須ページにアクセスできない。}}$ | M |
| FR-004 | プロフィール設定 | アバター画像・表示名・ステータスを変更できる。$\color{red}{\text{変更は他ユーザーの画面に反映される。アバター画像は 2MB まで、形式は jpg/png/gif/webp。検証は FR-107 と同様にサーバー側で内容(マジックバイト)により行う。}}$ | M |

### 4.2 メッセージング

| ID | 要件 | 受入基準 | 優先度 |
|---|---|---|---|
| FR-101 | チャンネル内テキストチャット | 参加チャンネルに投稿でき、他の参加者に即時表示される。$\color{red}{\text{投稿から他クライアントへの表示は通常 1 秒以内(§5 性能と同一基準)。}}$ | M |
| FR-102 | ダイレクトメッセージ | ユーザー間で会話できる。$\color{red}{\text{同一ワークスペース内の 1 対 1 のみ。}}$ | M |
| FR-103 | メッセージ編集 | 自分のメッセージを編集できる。$\color{red}{\text{「編集済み」と表示される。}}$ | M |
| FR-104 | メッセージ削除 | 自分のメッセージを削除できる。$\color{red}{\text{削除後は本文を破棄し、他ユーザーの画面・検索結果・API 応答から除外する。リアクション・メンションも無効にする。削除済みかどうかは deleted_at で判定する(スレッドの親が削除済みなら FR-105 の「削除されました」表示になる)。添付ファイルがある場合は、取得を即時に不可(404)にし、Attachment 行を物理削除する。同じトランザクション内で、削除対象の storage_key を削除キュー(StorageDeletion)に登録し、ストレージ上の実体は非同期で削除する。失敗時はキューの行が残るため再試行できる(添付に関する基準はフェーズ 4 の添付実装時に検証する)。}}$ | M |
| FR-105 | スレッド返信 | メッセージに対しスレッドで返信できる。$\color{red}{\text{親メッセージに返信数が表示される。親が削除された場合は「削除されました」と表示して返信は残す。}}$ | M |
| FR-106 | マークダウン記法 | マークダウン記法で書いたメッセージが整形表示される。$\color{red}{\text{対応: 太字・斜体・取り消し線・コード(インライン/ブロック)・リスト・引用・リンク。HTML は無害化する。}}$ | M |
| FR-107 | ファイル添付(画像・動画) | 画像・動画を添付でき、$\color{red}{\text{メッセージ内でプレビュー/再生できる。画像 10MB・動画 50MB・1 投稿 5 ファイルまで。形式は jpg/png/gif/webp、mp4/webm(§9 #6)。サイズ・ファイル数・形式の検証はサーバー側で必ず行い、拡張子や Content-Type ではなくファイル内容(マジックバイト)で判定する(クライアント側でも事前に確認してエラーを表示するが、それだけに頼らない)。上限を外れたファイルは拒否する。配信時は X-Content-Type-Options: nosniff を付け、許可形式以外を返さない。テストには、上限ちょうど(10MB / 50MB / 5 ファイル)と上限 +1 の両方を含める。}}$ | M |
| FR-108 | 絵文字リアクション | メッセージに絵文字を付与できる。$\color{red}{\text{解除もでき、付与者と件数が表示される。}}$ | M |
| FR-109 | メンション | メッセージ内で ＠ユーザー名 を指定できる。$\color{red}{\text{入力中に候補が補完され、表示は強調される。候補は「そのチャンネルの参加者」に限定する。プライベートチャンネルで非参加者をメンションしても、通知は送られず、チャンネルへのアクセス権も付与されない。}}$ | M |
| FR-110 | メッセージ検索 | メッセージを検索できる。$\color{red}{\text{結果は自分が閲覧権限を持つチャンネル・DM のメッセージに限る。日本語で 2 文字の語でもヒットする。削除済みメッセージはヒットしない。「\textbackslash」「\%」「\_」を含む語も文字どおりに検索できる。検索語は 2 文字以上とし、1 文字以下は検索せずに案内を表示する。結果は新しい順に 50 件ずつ取得する(§9 #7)。}}$ | M |

### 4.3 ワークスペース・チャンネル管理

| ID | 要件 | 受入基準 | 優先度 |
|---|---|---|---|
| FR-201 | ワークスペース作成 | 名前を指定して作成でき、作成者はオーナーになる。$\color{red}{\text{初期チャンネル(general)が作られる。1 人のユーザーが複数のワークスペースに所属でき、画面上で切り替えられる。プロフィールは全ワークスペースで共通。未読・メンションのバッジは、表示中でないワークスペースの分も出す(§9 #3)。}}$ | M |
| FR-202 | チャンネル作成 | 名前と種別(パブリック/プライベート)を指定して作成できる。$\color{red}{\text{同一ワークスペース内で名前は一意。}}$ | M |
| FR-203 | パブリックチャンネル参加 | $\color{red}{\text{メンバーはパブリックチャンネル一覧から自由に参加・退出できる。ただし general は退出・削除できない。}}$ | M |
| FR-204 | プライベートチャンネル招待 | 招待された人のみ参加でき、$\color{red}{\text{非参加者には一覧・検索結果に現れない。招待できるのは、チャンネルの作成者とオーナーのみ(オーナーは参加者でなくても招待できる)。参加者はいつでも退出できる。参加者の追放は MVP 対象外(§9 #5)。}}$ | M |
| FR-205 | (FR-301 に統合) | $\color{red}{\text{「友人の招待」と「ユーザーの招待」は同一機能のため FR-301 に統合。欠番。}}$ | - |

### 4.4 管理者権限(オーナー)

| ID | 要件 | 受入基準 | 優先度 |
|---|---|---|---|
| FR-301 | ユーザー(友人)の招待 | オーナーがユーザー(友人)をワークスペースに招待できる。$\color{red}{\text{方式は期限付き招待リンク。有効期限(1 日 / 7 日 / 30 日、デフォルト 7 日)と使用回数(1 回 / 10 回 / 無制限、デフォルト 10 回)を選べ、オーナーはリンクを無効化できる。期限切れ・回数超過・無効化されたリンクは受諾できない。受諾にはログインが必須。トークンは平文で保存せずハッシュで保存する。使用回数は条件付き更新(used_count が max_uses 未満のときだけ加算)で原子的に消費し、同時に受諾されても上限を超えない(テストで確認する)(§9 #1)。}}$ | M |
| FR-302 | ユーザーのキック | オーナーがメンバーを強制退出させられる。$\color{red}{\text{キックの検証可能な基準: (1) 既存セッションが失効する。(2) 確立済みの WebSocket 接続が切断される。(3) 全チャンネル(プライベート・DM 含む)の ChannelMember と、ThreadMember の行が削除される(過去メッセージは残す。§9 #11)。(4) キックされたユーザーは Membership の状態が kicked となる。招待リンクの受諾時に必ず kicked かどうかを確認し、有効なリンク(期限内・使用回数に余裕あり)でも再参加できない。(5) オーナー自身はキックできない。}}$ | M |
| FR-303 | チャンネルの追加・削除 | オーナーがチャンネルを追加・削除できる。$\color{red}{\text{削除時は確認ダイアログを表示する。削除後は、チャンネル配下の全データ(ChannelMember・ThreadMember・メッセージ・スレッド返信・リアクション・メンション・Attachment)が 1 つのトランザクションで DB から消え、削除したチャンネルへのアクセスは 404 を返す。同じトランザクション内で添付の storage_key を削除キュー(StorageDeletion)に登録し、実体は非同期で削除する。失敗時はキューの行が残るため再試行できる(§9 #8)。}}$ | M |
| FR-304 | $\color{red}{\text{キックの解除}}$ | $\color{red}{\text{オーナーがキック済みユーザーのキックを解除できる。解除すると Membership の kicked 行を削除し(workspace_id と user_id の組は一意のまま)、そのユーザーは新しい招待リンクから再参加できる。解除しただけでは自動では参加しない。操作はオーナーのメンバー管理画面から行う。status が kicked の行は、キックから解除までの間だけ存在する。過去メッセージは User に紐づくため、解除や再参加による表示名への影響はない。}}$ | M |

### 4.5 通知(ブラウザ上のみ)

| ID | 要件 | 受入基準 | 優先度 |
|---|---|---|---|
| FR-401 | 未読通知 | 未読メッセージがあるチャンネル/DM に未読表示が出る。$\color{red}{\text{未読数バッジを表示し、既読位置はチャンネル単位でサーバーに保存して別端末でも共有する。チャンネルの未読数はトップレベルのメッセージ(parent_id が空)だけを数える。スレッド返信の未読は、スレッド単位の既読位置で別に管理する(§9 #13)。検証基準: (1) 未読のあるスレッドがあれば、サイドバーの「スレッド」項目にバッジが出る。(2) 該当スレッドのスレッドパネルを開くと、そのスレッドのバッジが消える。(3) スレッド返信はチャンネルの未読数を増やさない。}}$ | M |
| FR-402 | メンション通知 | 自分宛メンションが通知される。$\color{red}{\text{強調バッジで表示し、ブラウザの Notification API による通知(ユーザー許可制)も行う。スレッド返信内のメンションも通知し、そのスレッドに参加していなくてもよい。ただし、メンション先がそのチャンネルの参加者であることが前提(FR-109 のとおり、チャンネル非参加者には通知しない)。}}$ | M |
| FR-403 | $\color{red}{\text{通知設定}}$ | $\color{red}{\text{チャンネル単位のミュート。ミュートしたチャンネルは、未読バッジを出さない。メンション通知は届く(§9 #14)。}}$ | S |

## 5. 非機能要件

$\color{red}{\text{前提: 個人開発・小規模(同時接続数十人、ワークスペース数個から十数個)。}}$

| 区分 | 要件 |
|---|---|
| 性能 | $\color{red}{\text{投稿から他クライアント表示まで通常 1 秒以内(目標)。履歴はページング(例: 50 件ずつ)で取得する。}}$ |
| セキュリティ(認証・Web) | $\color{red}{\text{パスワードは bcrypt または argon2 でハッシュ化。HTTPS 前提。XSS(マークダウンの無害化)・CSRF・SQL インジェクション対策。ログイン試行のレート制限。}}$ |
| セキュリティ(認可) | $\color{red}{\text{全 API で、リクエストごとにワークスペース・チャンネルの所属を確認する(IDOR 対策)。キャッシュした所属情報に頼らない。}}$ |
| セキュリティ(WebSocket) | $\color{red}{\text{ハンドシェイク時に Origin を検証する(Cross-Site WebSocket Hijacking 対策)。接続ごと・イベントごとにチャンネル参加を確認する。キックやチャンネル退出時は、購読中のルームから即時に除外する。}}$ |
| ファイル | $\color{red}{\text{拡張子だけでなく MIME とマジックナンバーも検証する。サイズ上限を設ける。取得は認可付き URL とし、削除済みメッセージの添付は取得不可にする。}}$ |
| 可用性 | $\color{red}{\text{高可用性は求めない。DB の定期バックアップを行う。}}$ |
| 互換性 | $\color{red}{\text{最新の Chrome / Edge / Firefox / Safari のデスクトップ版。}}$ |
| 保守性 | $\color{red}{\text{認可・マークダウン変換など重要ロジックに自動テストを書く。CI で lint とテストを実行する。}}$ |
| プライバシー | $\color{red}{\text{パスワード・トークンをログに出力しない。}}$ |

## 6. データモデル概要

$\color{red}{\text{以下は設計案。}}$

```
User ─< Membership >─ Workspace
Workspace ─< Channel ─< ChannelMember >─ User
Channel(DM 含む。種別: public / private / dm)
Channel ─< Message ─< Attachment
Message ─< Reaction (user, emoji)
Message ─< Mention (user)
Message(parent_id) ─ スレッド返信は親メッセージを参照
ChannelMember.last_read_message_id ─ チャンネルの未読管理(トップレベルのメッセージのみ対象)
ThreadMember(親メッセージ, user) ─ スレッドの未読管理
Workspace ─< Invitation (token_hash, expires_at, revoked_at)
```

| エンティティ | 主な属性 |
|---|---|
| User | id, username(unique), password_hash, recovery_code_hash, display_name, avatar_url, status_text |
| Workspace | id, name, owner_id |
| Membership | workspace_id, user_id, role(owner/member), status(active/kicked) |
| Channel | id, workspace_id, name, type(public/private/dm) |
| ChannelMember | channel_id, user_id, last_read_message_id, muted |
| ThreadMember | root_message_id, user_id, last_read_message_id |
| Message | id, channel_id, user_id, parent_id(nullable), body(nullable。削除時は null 化), created_at, edited_at, deleted_at |
| Attachment | id, message_id, kind(image/video), storage_key, mime, size |
| Reaction | message_id, user_id, emoji(複合ユニーク) |
| Mention | message_id, user_id |
| Invitation | id, workspace_id, token_hash, created_by, expires_at, max_uses(nullable。null は無制限), used_count, revoked_at(nullable) |
| StorageDeletion | id, storage_key, requested_at, deleted_at(nullable), retry_count(添付実体の削除キュー) |

DM は「2 人だけの type=dm の Channel」として扱い、スレッド・リアクション・検索・未読を共通化する。

## 8. 技術選定案

$\color{red}{\text{小規模・個人開発で、リアルタイム性と実装の単純さを重視した 1 案。得意な技術があれば変更可能。}}$

| 領域 | 採用案 | 理由 |
|---|---|---|
| 言語 | $\color{red}{\text{TypeScript(フロント・バック共通)}}$ | $\color{red}{\text{型を共有でき、学習コストが低い}}$ |
| フロント | $\color{red}{\text{React + Vite}}$ | $\color{red}{\text{エコシステムが豊富}}$ |
| バックエンド | $\color{red}{\text{Node.js + Fastify + WebSocket(Socket.IO など)}}$ | $\color{red}{\text{リアルタイム配信を同一プロセスで扱える}}$ |
| DB | $\color{red}{\text{PostgreSQL}}$ | $\color{red}{\text{リレーショナルなデータに適する}}$ |
| ORM | $\color{red}{\text{Prisma または Drizzle}}$ | $\color{red}{\text{型安全、マイグレーション管理}}$ |
| 認証 | $\color{red}{\text{セッション Cookie(HttpOnly, SameSite) + argon2}}$ | $\color{red}{\text{メール認証不要の構成で単純かつ安全}}$ |
| ファイル保存 | $\color{red}{\text{開発: ローカルディスク / 本番: S3 互換ストレージ}}$ | $\color{red}{\text{抽象化して差し替え可能にする}}$ |
| 通知 | $\color{red}{\text{WebSocket + Notification API}}$ | $\color{red}{\text{ブラウザ内通知の要件に合致}}$ |
| 検索 | $\color{red}{\text{PostgreSQL の ILIKE + pg\_trgm(§9 #7)}}$ | $\color{red}{\text{pg\_bigm はマネージド DB で使えないため採用しない。小規模なら 2 文字の語の全件走査も許容できる}}$ |
| テスト/CI | $\color{red}{\text{Vitest + Playwright、GitHub Actions}}$ | $\color{red}{\text{既存の CI 構成を活用}}$ |
